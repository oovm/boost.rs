## 冻结分层

```
语言 AST → HIR → MIR → 语言 × 目标适配器 → 目标构建接口 / 目标私有 LIR → 编码器 → 容器/自检
```

- 共享层（compiler.types / compiler.target / compiler.analysis / compiler.planning / compiler.emitter
  接入协议）只保留确有消费者的算法与窄视图事实。
- 禁止：新公共操作枚举、胖计划、按语言名分派、运行时回猜。
- `.nyar` 只分发语言 IR 与分析结果；运行器只接收对应执行制品。

## 依赖边账本（本批变化）

- **已去边**：`compiler-emitter → compiler-optimize`（本批 efa4c217：`EntryReturnProjection` /
  `ProjectionPolicy` 改由 `compiler-target` 直接引入，`AssembledFragment` 不再携带 `TheoryBundle`）。
- **已删除**：带 Lua 语义的 `ResidualSink`（本批 1324eb0b）。
- **已收窄**：`compiler-planning` 入口不再依赖 `LinkedSemanticProgram` 全量（本批 121c260b）。
- **已移出内核**：OVM DOM 分派改 `HostProvider` 显式注册（本批 52f960c6）。
- **布局合同化**：`Utf8TextCarrierLayout` 由语言结算、machine 宿主桥/控制台路径按事实读写
  （本批 f36eba83）；wasm_js_glue 文本语义裁定为宿主 JS 库行为合同，非布局复制。
- 保留边：emitter → types/target/planning/analysis/gc/data-binary-odin；语言 → emitter（单向）；
  Legion/Asgard → ovm VM。

## 裁定与遗留

- `LaneContext` 不是胖计划等价包装：它是语言 crate 内部对自家 MIR 的窄借用视图，
  不跨 crate 流通，不携带公共操作枚举。
- `EntryReturnProjection` 本体定义在 compiler.types，属运行合同事实，driver 消费合法；
  违规的是 emitter 经 compiler-optimize 的取道，已消除。
- TypeScript 对抗线：`language.typescript` 提交面当前只有 formatter；并行会话正在主检出
  拆分 TS crate（AST/HIR/MIR/codegen）。TS × OVM 第一投影（Futamura）须在该工作入库后
  以 `TS × OVM` 适配器接入同一 OVM builder/验证器/编码器，禁止回填按语言语义命名的
  残差操作枚举。
- `open-domain-94f5f65` worktree 为独立未合入工作（session/geometry/mesh/WebGPU 域），
  保留待所属工作合入后处置。
