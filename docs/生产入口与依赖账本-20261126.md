## 冻结分层

```
语言 AST → HIR → MIR → 语言 × 目标适配器 → 目标构建接口 / 目标私有 LIR → 编码器 → 容器/自检
```

- 共享层（compiler.types / compiler.target / compiler.analysis / compiler.planning / compiler.emitter
  接入协议）只保留确有消费者的算法与窄视图事实。
- 禁止：新公共操作枚举、胖计划、按语言名分派、运行时回猜。
- `.nyar` 允许在语言与版本命名空间内分发语言 MIR 与分析结果；禁止变成 emitter 必须消费的统一指令集；
  运行器只接收对应执行制品。
- 共享层保留算法、标识、诊断、窄事实与协议；每个生产入口的输入字段必须有唯一裁决方（见下表）。

## 裁定与遗留

- `LaneContext` 不是胖计划等价包装：它是语言 crate 内部对自家 MIR 的窄借用视图，
  不跨 crate 流通，不携带公共操作枚举；继续为 Valkyrie 适配器服务，留在语言内部（签收）。
- `CanonicalFragment` 无指令体，不构成第二个完整 God IR；问题是规划消费面过宽（D1/D2）。
- `EntryReturnProjection` 本体定义在 compiler.types，属运行合同事实，driver 消费合法；
  违规的是 emitter 经 compiler-optimize 的取道，已消除。
- 题库证据按实际产物签收：报告标 `native` 的 50/100/300 批次实测对象为 `target=node` 的
  `.node`，绿题 16/25/68；普通 C ABI DLL 单独代表组 4/4、272 例；CPython 3/3、192 例。
  Node runner 从清单定位产物、按精确名找导出并实际 `require()` 调用；DLL 消费端 `dlopen`；
  Python 消费端 `importlib` 从 `.pyd` 加载。矩阵执行通过率只覆盖已执行用例，报告只覆盖
  列明的目标与平台；标签整改见 D9。
- TypeScript 对抗线：工作树导入按候选工作处理；提交面当前只有 formatter，
  `compiler.specialize` 只有合同文档。候选代码的独立 VM、GC、JIT、FFI 须逐项审其用途后
  决定保留；TS 保留自己的 AST/HIR/MIR 与解释语义，解释器作为投影输入与差分基线。
  TS × OVM 第一投影（Futamura）须在该工作入库后以 `TS × OVM` 适配器接入与 Valkyrie
  **同一套** builder/验证器/编码器，禁止回填按语言语义命名的残差操作枚举。
- `open-domain-94f5f65` worktree 为独立未合入工作（session/geometry/mesh/WebGPU 域），
  保留待所属工作合入后处置。
- 合入纪律：按 Boost 合同与实现 → Valkyrie pin 与发行产物 → leetcode.v 消费证据的顺序
  线性合入 `dev`；从干净检出按最终 SHA 重建，记录产物哈希与对应 CI；对含独有提交或
  未提交改动的 checkout，先由归属方合入、归档或明确废弃，再清理。
