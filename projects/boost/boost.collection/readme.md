# `boost-collection`

Boost 家族的规则集合能力：逻辑模型、访问能力、表示布局与存储载体分开描述。当前只交付**首个内存实现**（自有、连续行主序、`usize` 范围），不把连续、dense 或常驻内存写成 ArrayND 的普遍前提，也不引入 `ndarray`/`nalgebra`。

## 分层

| 层 | 内容 | 当前状态 |
|----|------|----------|
| 逻辑模型 | 规则 N 维坐标域、shape、坐标到元素的对应关系 | 合同已冻结，代码以内存实例表达 |
| 访问能力 | 读、写、遍历、越界与失败方式 | 内存实现提供引用式访问与检查式失败 |
| 表示与布局 | 行主序、strided、分块、稀疏 | 仅连续行主序 |
| 存储载体 | 自有/借用内存、映射文件、分页磁盘、设备 | 仅自有内存 |

逻辑元素数与已分配槽数、逻辑遍历序号与物理地址是不同事实；稀疏缺省、shape 变更、视图失效与 I/O 失败语义尚未进入代码。等第二种真实表示出现再抽能力 trait，不先造 God trait 或空后端。

## 两个作者面

| 类型 | 形状位置 | 存储 | 适用 |
|------|----------|------|------|
| `ArrayND<T, N>` | 运行时构造（`N` 是轴数） | `Vec<T>` 连续区 | 维数固定、各轴长度运行时确定 |
| `Array2D<T, ROWS, COLUMNS>` | 编译期类型参数 | `[[T; COLUMNS]; ROWS]` | 小尺寸、形状属于类型合同 |

稳定 Rust 不允许元组作为 const 泛型参数，因此 `Array2D<f32, (3, 3)>` 不成立。需要元组书写时用宏：

```rust
use boost_collection::array;

type Grid = array!(f32, (3, 3));

let mut grid = Grid::filled(0.0);
grid[[1, 2]] = 5.0;
assert_eq!(grid.shape(), [3, 3]);
```

`array!(f32, 3, 3)` 与元组写法等价，展开结果都是普通 `Array2D` 类型。

## 不变量

- `ArrayND` 的 `N` 是轴数，不是任何一轴的长度；各轴长度只在构造时确定，之后不变。
- 逻辑元素数严格等于各 extent 的乘积；零 extent 先识别，空数组仍保留各轴信息（`[0, 5]` 与 `[3, 0]` 都为 0 元素但形状不同）。
- 形状乘积、索引偏移与容量检查全部使用检查算术；坐标先逐轴验界再计算偏移。
- 元素可写，但不提供行级 `push`/`pop`，也不交出能改变缓冲长度的入口；`as_mut_slice` 只能改元素。
- 初始化不要求 `T: Default`/`T: Clone`；构造失败或 panic 时已初始化元素恰好释放一次。
- `ArrayND` 遍历与 `into_vec` 都按行主序；跨行有间隙的语义留给后续视图模型，不在索引路径隐式分配或复制。

## 边界

- 视图（裁剪、转置、`reshape`、可变别名）尚未提供，后续先定义坐标映射，不假定都能用 affine strides 表达。
- 稀疏、分块、CSR 等表示与映射文件/分页/设备载体尚未交付；不提供 `backend = disk` 之类标签冒充支持。
- 邻接表、文档列表、变长字节串等真正不等长的数据保留分段语义，不补成矩形。
- 矩阵运算、张量执行、图语义、数据库列语义与 GPU 布局仍归各领域 owner。
- 当前以 `std` 为宿主；`no_std + alloc` 目标尚未取证，不声称已支持。
